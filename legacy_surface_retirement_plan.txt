2. Legacy surfaces that must remain

These should not be retired or routed differently in the near term.

Legacy callables behind registry:
- All legacy callables listed above must remain as compatibility runners.
- Do not delete legacy bridge functions, operator methods, scheduler methods, TaskRunner methods, or StepExecutor paths.
- Reason: RuntimeRouteRegistry is now the admission layer, but legacy callables still own behavior and compatibility contracts.

Read-only/status/reporting paths:
- control inspect / monitor / list / evidence
- work_package status / progress / summary / report / memory / memory-status / list
- goal list / status / deps
- portfolio list / show / state / summary
- program list / show / state / summary / tree / observability
- task graph / list / audit
- Reason: not execution-producing; Package 9 verifies representative inspect/list paths do not trigger registry.

Control/state mutation paths:
- control cancel
- work_package pause / resume / cancel
- goal pause / resume / cancel / defer
- task cleanup / archive-stale
- Reason: control-plane or maintenance operations, not execution-producing runtime admission.

CLI smoke task creators:
- task dag-smoke
- mutation-smoke / controlled-mutation-smoke
- source-mutation-smoke
- mutation-transaction-smoke
- engineering-batch-smoke
- runtime-plan-smoke
- runtime-session-smoke / runtime-session-resume
- runtime-session-finalize / recovery-finalize
- runtime-supervisor-smoke
- Reason: create queued records and sometimes seed target files; they do not execute the created work.

Execution machinery internals:
- RuntimeDispatcher.run_scheduler_boundary
- Scheduler._run_step_via_task_runner
- Scheduler._run_scheduler_owned_simple_task_until_stop
- Scheduler._run_task_via_agent_loop and fallback/yield helpers
- TaskRunner internal _run_one_step, mutation boundary integration, terminal evidence/completion sealing
- StepExecutor / ExecutionFabric
- Reason: these are machinery behind admitted routes. Retiring or wrapping them as surface admissions would risk authority, recursion, and execution semantics.

Pure decision helpers:
- repair preflight decision helpers
- route candidate predicates
- planner/persistent candidate checks
- Reason: not execution-producing. Only execution-producing response/callable surfaces are registry admissions.

4. Retirement sequence

Recommended order:
1. Mark direct native-mainline-only surface helpers as deprecated in comments/docs after follow-up seals pass.
2. Keep legacy callables in place behind RuntimeRouteRegistry.
3. Keep read-only/control paths direct and explicitly documented as non-execution surfaces.
4. Add focused alias/variant seal tests before removing any compatibility wording.
5. Defer any machinery-level retirement until a separate execution-authority refactor exists.

Do not do yet:
- Do not delete legacy callable implementations.
- Do not remove route markers or legacy response fields.
- Do not wrap read-only/control paths in RuntimeRouteRegistry.
- Do not migrate StepExecutor/ExecutionFabric internals as surface admissions.
