5. Recommended Package 2 changes to make RuntimeNativeMainline canonical

Priority 1 - Add a single mainline admission adapter
- Introduce a small adapter, e.g. core/runtime/runtime_native_entry_adapter.py, that exposes:
  - run_user_request(...)
  - run_task_record(...)
  - run_scheduler_task(...)
  - run_engineering_goal(...)
  - run_work_package(...)
  - run_cli_request(...)
- Internally all execution-capable methods should call RuntimeNativeMainline.run_goal(...) or RuntimeNativeExecutionDispatch.dispatch_*.
- Keep request normalization here so AgentLoop, Scheduler, and CLI files do not each invent mainline bootstrapping.

Priority 2 - Wire AgentLoop pre-routes to mainline
- Convert _try_handle_engineering_goal_route(...) to RuntimeNativeMainline/RuntimeNativeExecutionDispatch, preserving the existing engineering_program_mainline response shape as adapter metadata.
- Convert _try_handle_engineering_task_route(...) from direct engineering_task_runner.run_engineering_task(...) to RuntimeNativeMainline.run_legacy_request(...).
- Convert _try_handle_work_package_route(...) to a mainline dispatch or schedule-item dispatch. RuntimeWorkPackageOperator can remain downstream, but AgentLoop should not call run_package directly.
- Convert _run_task_mode_via_scheduler(...) to create/submit intent through a mainline dispatch adapter, or mark Scheduler as a delegated service below RuntimeNativeMainline.
- Retain legacy routes behind explicit compatibility flags only, with result metadata such as runtime_native_mainline_bypass=True until retired.

Priority 3 - Gate Scheduler public execution behind mainline
- Add Scheduler.run_via_mainline(...) or replace external callers of tick/run_next/run_one_step with RuntimeNativeExecutionDispatch.dispatch_schedule_item(...).
- Keep Scheduler.tick(...) available as an internal/delegated implementation, but add a guard/metadata contract distinguishing:
  - called_by_runtime_native_mainline=True: allowed delegated execution.
  - external direct call: compatibility path, logged as bypass.
- Move direct RuntimeDispatcher construction in Scheduler._run_step_via_task_runner(...) below mainline-owned dispatch context or inject RuntimeNativeExecutionDispatch.

Priority 4 - Restrict TaskRunner public execution to delegated use
- Keep TaskRunner as endpoint service below RuntimeDispatcher/mainline.
- Add or enforce authority metadata requiring RuntimeNativeMainline/RuntimeNativeExecutionDispatch lineage for side-effecting steps.
- Preserve execute_owned_step(s) for tests/internal adapters, but mark direct external use as compatibility only.

Priority 5 - Update CLIs to enter through mainline
- task_cli:
  - Route non-read-only `task run`, drain, runtime session resume/recovery execution through RuntimeNativeMainline or RuntimeNativeExecutionDispatch.
  - Keep list/graph/status read-only fast paths.
- goal_cli / portfolio_cli / program_cli:
  - Route run/run-next/cycle/run-until-idle through RuntimeNativeMainline.
  - Preserve existing summary output by summarizing mainline result metadata.
- work_package_cli:
  - Route submit/run/run-validation/dispatch-request through mainline or dispatch adapter.
  - Keep status/summary/report/memory/list read-only direct.
- control_cli:
  - Route submit through mainline-backed TaskControlAPI or mainline adapter.
- verification_cli:
  - Leave as verification subsystem if intentionally outside engineering-runtime mainline, but mark as verification-only command execution and prevent it from being used as a runtime task execution route.

Priority 6 - Add bypass accounting
- Every compatibility direct path should attach:
  - runtime_native_mainline_bypass=True
  - bypass_reason
  - intended_package_2_target
  - authority_path
- Add a small inventory/health command that reports remaining bypass counts by surface.

Priority 7 - Tests for Package 2
- Add focused tests proving these external entries reach RuntimeNativeMainline:
  - AgentLoop JSON engineering_task
  - AgentLoop JSON engineering_goal/adaptive route
  - AgentLoop work_package route
  - Scheduler submit/tick route
  - task_cli task run
  - goal_cli run
  - work_package_cli run
- Add negative tests that direct TaskRunner side-effect calls without mainline/dispatch lineage are rejected or marked compatibility-only.
