RuntimeNativeMainline Retirement Inventory
==========================================

Status: AER Phase 2 / Package 1
Purpose: inventory only
Code changes: none
Pytest: not required
Recommended validation: git status --short

============================================================
1. Current Architectural Position
============================================================

Runtime admission migration is complete.

Current canonical admission path:

Surface / AgentLoop / CLI / Scheduler / TaskRunner
    -> RuntimeRouteRegistry
    -> RuntimeNativeMainline.run_compatibility_entry
    -> legacy callable / existing execution machinery

RuntimeNativeMainline is no longer the route owner.
RuntimeRouteRegistry is now the admission owner.

RuntimeNativeMainline currently remains as a compatibility and audit wrapper.

============================================================
2. RuntimeNativeMainline Responsibilities Still In Use
============================================================

The following responsibilities must not be removed until they are migrated or sealed elsewhere.

2.1 Compatibility semantics

- dict return receives additive metadata only
- non-dict return is returned unchanged
- exception is recorded and re-raised
- failed compatibility event is emitted before re-raise

Retirement blocker:
These semantics currently define the compatibility boundary and must remain stable.

2.2 Admission metadata

- runtime_native_mainline_canonical_entry
- compatibility entrypoint metadata
- request/goal metadata
- runtime route metadata passed from RuntimeRouteRegistry

Retirement blocker:
Equivalent metadata must exist in RuntimeRouteRegistry or runtime_native_entry_adapter before slimming.

2.3 Event / audit record

- successful compatibility admission event
- failed compatibility admission event
- saved run record for compatibility invocation

Retirement blocker:
A replacement event/audit owner must exist before removing the wrapper.

2.4 Delegate recursion protection

- _runtime_native_mainline_delegate active flag
- Scheduler delegate keyword compatibility
- TaskRunner delegate keyword compatibility
- AgentLoop delegate guard

Retirement blocker:
Registry-level or adapter-level delegate guard must be sealed before removal.

4. RuntimeNativeMainline Usage Categories
============================================================

4.1 Safe to slim later

RuntimeNativeMainline.run_compatibility_entry

Reason:
It is now called primarily from RuntimeRouteRegistry. It can eventually become a thin delegate to runtime_native_entry_adapter.

Required before slimming:
- adapter owns compatibility result shaping
- adapter owns exception event shaping
- adapter owns metadata merge
- existing Package 2.1 semantics still pass

4.2 Must remain for now

RuntimeNativeMainline.boot
RuntimeNativeMainline.run_goal
RuntimeNativeMainline.run_legacy_request
RuntimeNativeMainline persistence/event helpers

Reason:
These may still be used by existing native runtime tests or direct runtime-native flows outside the surface registry migration.

Required before retirement:
- explicit search/inventory of direct run_goal/run_legacy_request users
- seal tests proving registry-admitted surfaces do not require direct boot/run_goal
- migration plan for any remaining native loop callers

4.3 Do not delete yet

RuntimeNativeMainlineConfig
RuntimeNativeMainlineRunResult
RuntimeNativeMainlineEvent
stable_mainline_fingerprint
utc_timestamp

Reason:
These define public contracts and storage schema. Removal would be a breaking contract change.

5. Candidate Extraction Target
============================================================

Preferred target:

core/runtime/runtime_native_entry_adapter.py

Responsibilities to move there later:

- compatibility runner invocation
- dict metadata merge
- non-dict passthrough
- exception capture and re-raise
- compatibility event payload construction
- delegate guard helper utilities

RuntimeNativeMainline after extraction should only:

- construct or receive adapter
- call adapter.run(...)
- persist returned event/run data if needed
- preserve public API

============================================================
6. Retirement Blockers
============================================================

Blocker 1:
RuntimeRouteRegistry currently delegates into RuntimeNativeMainline.run_compatibility_entry.

Blocker 2:
Compatibility event persistence is still located in RuntimeNativeMainline.

Blocker 3:
Scheduler / TaskRunner overlays still require delegate keyword compatibility.

Blocker 4:
Direct native runtime callers may still use run_goal or run_legacy_request.

Blocker 5:
Existing tests assert RuntimeNativeMainline contracts by name.
