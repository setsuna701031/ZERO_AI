1. Canonical AER mainline paths

Confirmed canonical admission chain:
- RuntimeRouteRegistry.run(route_key, request, workspace_root, goal)
  - resolves RuntimeRouteRecord
  - creates registry_runner
  - calls RuntimeNativeMainline.with_workspace(root)
  - enters RuntimeNativeMainline.run_compatibility_entry(...)
  - adds runtime_route_registry_admission / runtime_route_key metadata for dict results
  - preserves non-dict return values
  - relies on RuntimeNativeMainline compatibility semantics for exception re-raise

Confirmed RuntimeNativeMainline core:
- RuntimeNativeMainline.boot initializes recovery, lease, watchdog, supervisor, execution fabric, transaction fabric, ownership fabric, AER integration, and RuntimeNativeAgentLoop.
- RuntimeNativeMainline.run_goal owns runtime-native execution flow and authority checks.
- RuntimeNativeMainline.run_compatibility_entry is the required compatibility/admission wrapper for migrated legacy surfaces.

Confirmed Scheduler/TaskRunner surface wrappers:
- Scheduler public wrapper path:
  Scheduler public method -> Scheduler._run_via_runtime_native_mainline -> RuntimeRouteRegistry -> RuntimeNativeMainline.run_compatibility_entry -> delegated legacy body.
- TaskRunner public wrapper path:
  TaskRunner public method -> TaskRunner._run_via_runtime_native_mainline -> RuntimeRouteRegistry -> RuntimeNativeMainline.run_compatibility_entry -> delegated legacy body.

Important boundary:
- RuntimeRouteRegistry is admission, not execution machinery.
- Legacy callables still own behavior.
- RuntimeDispatcher/Scheduler/TaskRunner/StepExecutor internals remain execution machinery behind admitted routes.
