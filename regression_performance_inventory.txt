Likely Root Cause
-----------------
The slow/full-suite behavior is likely not a single test. It is an accumulation of:
1. Many pytest-collected CLI/subprocess tests that spawn Python, app.py, git, or command gateways.
2. Repo-wide static inventory tests that scan large portions of the workspace with rglob/os.walk style patterns.
3. LLM/Ollama contract tests that are mostly mocked, but are not consistently marked and are mixed into the normal collection taxonomy.
4. External/local-server tests such as tests/test_chat.py, currently ignored rather than marked external.
5. Long validation/integration scenarios under tests/validation and work-package/runtime replay files.

Non-mainline Issues
-------------------
- tests/test_chat.py contains mojibake/corrupted payload text and performs an external HTTP request at import/module execution time. It is ignored by pytest.ini, but should still be converted to a marked/skipped test or moved out of pytest collection.
- pytest.ini does not define an `llm` marker, so LLM/Ollama-semantic contract tests cannot be cleanly excluded with marker expressions today.
- Many subprocess-heavy tests lack `integration` markers, making default `pytest tests -q` vulnerable to high CPU and slow process spawning.
- tests/test_runtime_replay_execution_bridge.py is very large and includes many monkeypatched subprocess/timeout paths; even if mocked, it is a likely CPU hotspot during collection and execution.
- tests/validation long-running goal tests are not marked integration/slow despite their scope.
